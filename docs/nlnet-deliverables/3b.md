# 3b. Configure bonfire ingestion

The original plan was to ingest posts from Bonfire. The work changed: we now show posts from several networks on Sciety. See [5c](./5c.md).

We wanted to show public posts about a preprint, from social networks built on open protocols, on that preprint's activity page in Sciety. We built this for four networks: Bluesky and Semble (both use ATProto), and Bonfire and Mastodon (both use ActivityPub).

A "mention" here means a post that links to the preprint.

## How it works

Sciety does not copy these posts into its own records. When someone opens a preprint's activity page, Sciety asks the source network for any posts about that preprint and shows them there.

## What we built

**Bluesky** ([#4260](https://github.com/sciety/sciety/issues/4260))

- Posts are found and shown when the page loads. We don't need a list of papers in advance.
- Bluesky mentions are common. You will find them on most eLife reviewed preprints, for example [10.7554/elife.112941.1](https://sciety.org/articles/activity/10.7554/elife.112941.1).

**Semble** ([#4258](https://github.com/sciety/sciety/issues/4258))

- We asked Semble once for every card that has a DOI, and kept only the DOIs Sciety is likely to support. That gave us 11 papers, for example [10.1101/2024.12.06.627200](https://sciety.org/articles/activity/10.1101/2024.12.06.627200).
- That list is built into Sciety. When one of those papers' pages loads, Sciety checks Semble for the mention and shows it.
- We kept the list fixed so that we don't overload Semble. Updating it needs a small piece of developer work ([#4259](https://github.com/sciety/sciety/issues/4259)).

**Bonfire** ([#4265](https://github.com/sciety/sciety/issues/4265))

- We first looked at pasting the text of some posts into Sciety by hand. It would have looked right but taught us little about how to connect, so we retrieve them from Bonfire instead.
- We set Sciety up as an ActivityPub "actor", an identity that lets it make signed requests to ActivityPub servers.
- We found very few mentions of Sciety papers on Bonfire instances: three. Those three papers are built in, and their posts are fetched from Bonfire when the page loads.

**Mastodon** ([#4266](https://github.com/sciety/sciety/issues/4266))

- The same approach as Bonfire, for six papers, for example [10.24072/pcjournal.305](https://sciety.org/articles/activity/10.24072/pcjournal.305).

## What works

- Live retrieval of posts from all four networks.
- Live discovery of Bluesky posts, with no list of papers needed.
- For Semble, a separate way to refresh the built-in list of papers.
- For ActivityPub, Sciety signs its requests as an actor, so Bonfire and Mastodon both answer.

## What doesn't work yet, or surprised us

- Finding ActivityPub posts automatically. ActivityPub has no search across the whole network. A server only sees posts that reach it, so we searched the fediverse ourselves for mentions of papers Sciety supports and built in a representative nine (three Bonfire, six Mastodon). Automatic discovery should be possible through the Sciety actor's inbox, but we ran out of time.
- Finding Semble posts as they appear. This would probably work as a regular background job, separate from page loading. As we only found 11 relevant papers, it didn't seem worth doing.

## If someone wants a post removed

Sciety doesn't keep these posts. If a post is deleted on its own network so that it can no longer be fetched from there, it disappears from the Sciety page the next time the page loads.

Sciety has no way to hide a single post, or block an account, other than the post being removed at the source. [Devs to confirm.]

## Where it runs

It runs on sciety.org and is visible to everyone. There is no on/off switch, so turning it off means a code change. [Paul to decide: stay live, or take it off production until moderation controls exist.] [Devs to confirm: does the site say what is shown and how to ask for a post to be removed?]
